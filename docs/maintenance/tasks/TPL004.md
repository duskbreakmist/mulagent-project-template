## 复核结论与增量建议（尚未实施）

对 TPL003 五条建议的复核：1（维护层检查）前提已核实为真，认同；2（多人维护入口）单人阶段只需维护 CURRENT 一行链接即可，认同但不必立刻建索引；3（场景验收）认同，但应排在 init/update 回归之后，因为用户高频路径是安装与升级；4（入口文案）认同，template_readme 开头"可直接复制"宜补一句"按 manifest 复制"；5（relay 与自动调度分离）认同。

增量建议（TPL003 未覆盖）：

1. **维护身份识别不要依赖 git remote。** AGENTS.md 用"origin 指向 duskbreakmist/..."判断母模板身份；fork、改 remote 或以其他方式 clone 做实验时该判断会失效，新会话会把维护任务写进根种子。建议改用仓库内自证标记（docs/maintenance/README.md 存在，或在 .agents/template-state.json 自报角色），remote 仅作辅助。验收：删除或改名 remote 后，新会话仍走维护路径且不污染种子。
2. **legacy 内完整旧模板快照会造成"改错文件"风险。** docs/maintenance/legacy/live2d-normaldrive/gpt/project_templateA/ 保存了与当前骨架同名的完整副本（AGENTS.md、.agents/PROTOCOL.md、template_readme.md 等），检索和上下文召回会同时命中两份同名文件。建议在 legacy 入口与副本入口统一标注"归档快照，非当前源"，并让 check_template.py 对基名冲突给出提示。验收：检索 PROTOCOL.md 能一眼分辨当前源，检查器能报出重复基名。
3. **共享维护 CURRENT 的并发写入保护。** 本轮观察到 TPL003 由 staged 变为已提交，说明存在并行会话或异步收尾；多人同时改维护 CURRENT 会静默覆盖。建议在该文件顶部写明"写入前先 git status 并确认 HEAD 未变，提交只 add 自己改动的文件，不用 git add ."。验收：两次并发写入不产生静默覆盖。
4. **测试临时目录残留。** 根目录 .test-tmp/ 已按 .gitignore 忽略，但遗留 8 个空临时目录，说明测试未清理。低优先级，建议用 tempfile 上下文或收尾清理。
