# 整合者与继任（按需阅读）

## 指定与唯一性

- 用户当前指定优先；已有任务授权范围内，独立任务 owner 可兼任 integrator，注明选择来源，不自封为工程永久指挥者。
- 项目共享文件的默认汇总者记在 [.agents/coordination.md](../coordination.md)；登记表描述参与者，不承担实时领导记录。
- task 的 integrator 负责该任务整合；项目记录负责登记表、共享 CURRENT、共享配置和跨任务冲突。多个任务可以有不同 integrator，但同一共享文件同一时刻只有一个实际写者。
- 授权别人写共享文件时明确具体文件／区段、任务和有效阶段；不同文件可并行；同一文件即使分配不同区段也串行写入。“共同 integrator”不能作为并发覆盖许可。
- 拷贝模板初始 state: vacant。首位独立执行者只在本次用户任务范围内登记 active；发现已有负责人时先读取，而不是覆盖。active 表示记录的当前职责，不证明进程在线或持续监控。记录本身不是互斥锁。

## 继任与空窗

1. 能正常退出时，现任保存检查点／最后交接，停止相关写入，记录 handoff_pending 和候选建议。
2. 用户已指定继任或已明确预授权备用人／顺序时，按已有授权执行，不为同一接班重复请求批准；没有指定／预授权时请用户确定，不能凭额度、超时或沉默自我接管。
3. 接手者确认旧执行者停止、Git 状态与最新交接，写自己的接收确认，再串行更新协调记录和相关 task 的 integrator／来源／状态／交接链接。
4. 旧执行者额度耗尽或异常退出，可能无法再写最后交接；用已有检查点和 Git 事实恢复，不要求它再次回应作为永久前置条件。仍需用户指定／已有授权，并确认它不会继续写入。
5. 不设默认 24 小时等待，也不按时间自动判定失联或授权。无法确认停写或出现两个指挥者时暂停争议共享文件写入，请用户裁决。
6. 空窗期间可继续已经授权、与争议无关的独占产出和只读调查，保存自己的消息／交接；不擅自改共享状态或扩大范围。

## 争议、完成和故障

- 任何 Agent 在自己文件提出异议、证据和验证方法。integrator 在相关 task 的 Problems 记录处理结果，不能把不同意见改写成双方共识；权限／范围争议或验证无法解决的设计争议交用户决定。
- 交付是否 done 取决于交付范围和验收；没有推荐继任者不能把已完成任务倒退为 blocked。项目协调空窗用协调记录的 state 表示，与 task status 分开。
- 推荐提前／定期保存检查点。记录来源、前后负责人、时间与交接链接，不把最后一句告别当唯一恢复依据。
- 这些规则不提供 CAS、事务或权限隔离。跨机器、多个协调者或自动继任服务需要实际状态存储和执行者停止机制；本模板不实现此服务。
