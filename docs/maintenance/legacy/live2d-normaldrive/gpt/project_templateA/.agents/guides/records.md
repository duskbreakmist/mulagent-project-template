# 记录成本与生命周期（按需阅读）

## 单人串行路径

同一 owner 单独处理、无外部交接且无独立对照时，使用 [精简任务模板](../tasks/TEMPLATE-lite.md)。保留模式来源、scope、验收、实际验证和未验证项；若出现多人、依赖或对照，再补完整字段，不要求重写重复记录。

普通完成只更新 task、任务索引状态和 CURRENT 短摘要，并保存 Git 提交；不每次追加登记表或重写协调记录。索引只改一行，不复述正文。登记只在身份／能力变化时更新，协调记录只在职责／授权／默认模式／继任变化时更新。

交接文件只在**中断且有剩余工作、责任转移、跨 Agent 接力或复杂检查点不足以由 task 恢复**时必需；同一 owner 正常完成可以由 task 收尾。额度异常退出无法补最后交接时，先用既有检查点恢复，不制造不可能的前置条件。

## CURRENT 与历史

- CURRENT 保留活跃／阻塞任务入口、最近 3 个完成任务摘要与必要待办；每个已完成摘要不超过 10 行，通常整份控制在 60 行以内。
- 详细命令输出、哈希、测量与实施过程放 task 或正式交付物，通过链接导航。不把完整 task 粘贴进 CURRENT。
- 更早的已完成摘要移入 docs/history/CURRENT-YYYY-MM.md，保留原文、来源文件和归档时间；归档前核对当前内容、单写者及未提交改动，不覆盖其他作者内容。
- 归档中的相对链接若要继续可点击，按新位置调整并核对；保留原始上下文时也可放入标明来源的 Markdown 代码块。不要把路径变化当作删除历史的理由。
- 活跃阻塞不得因“只留最近 3 项”被隐藏；超过建议长度时压缩重复信息，保留恢复必需内容。季度／版本回顾是按需维护，不默认启动定时任务。

归档目录说明见 [docs/history/README.md](../../docs/history/README.md)。

## 登记、索引与稳定路径

agents_list.md 只记身份、能力来源及 2–3 条代表性证据，最多 2 条最近登记变化；不追加每次完成任务的流水。现存流水需要整理时先保存在历史文件，不能用新表覆盖丢弃事实。

tasks/README.md 索引所有活跃任务和最近 10 个完成任务；更多历史以任务文件／Git 查询。task 是状态事实源，索引更新时只复制 ID、标题、状态、owner、时间与链接，不在两处维护不同结论。

**默认保留 tasks/<ID>.md 的稳定路径**，不按版本数自动移动完成文件。确有归档需求时，先检查所有引用、更新索引与链接，或保留原路径跳转；项目版本周期不同，不能统一套用“两个版本就迁移”。

## 标识、提议与可选字段

独立会话使用不同稳定 Agent ID，文件署名与登记 ID 一致；旧简写作为 alias 留痕，不批量改历史。主会话内临时子任务可由主 owner 汇总，不必为每个短期执行者新建工程登记／CURRENT，但其 scope 与产出仍需明确。

未分配正式任务号的意见／工作提议可用 TMP-<agent-id>-<YYYYMMDD>-<topic-or-seq>，在本人消息或反馈文件记录，不擅自创建共享任务。转正时 integrator 分配 ID，在正式 task 添加 alias 与原记录链接；日期前缀单独使用容易碰撞。

version_tag 在实际打标签时记录真实值，无标签填“无”；需要时另记 release_commit。字段存在不授权每个任务强制打标签、推送或发布，工程明确版本规则仍优先。mechanisms 可选记录本次实际用到的机制，不新增必填问卷。

## 低摩擦反馈

一句话意见可以直接放在本人 task／handoff 的“模板备注”中（worker 仅在自己的可写文件中记录）；值得跟进时再链接或汇入本人 feedback 文件，原记录保留。不为一条意见额外造交接、任务或评分表。

长期不用的 plans／runs／results 等继续按需启用，不要求新 Agent 打开它们。是否删减取决于真实需求和使用反馈，零使用不是故障证据，也不预设一定节省了多少 token。
