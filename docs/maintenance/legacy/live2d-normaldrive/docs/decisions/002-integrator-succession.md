# ADR-002：共享整合者的指定、继任与争议

- 日期: 2026-10-01
- 状&#x6001;**: accepted_with_amendments（在用户本轮授权范围内实施）**
- **提案来源: WB 的 wb-001；修订与实施: gpt / COLLAB004**
- **原提案: Git 快照 a8373bf；不代表 WB 已二次确认修订版**

## **问题**

单写者可以减少共享状态覆盖，但需要定义负责人来源、写入边界、额度耗尽或异常退出后的接班，以及 worker 的异议路径。登记表中的身份／能力不应承担实时领导状态。

## 决定

1. 项目共享文件汇总者写入 [.agents/coordination.md](../../.agents/coordination.md)，明确指定来源、有效范围、状态与交接。任务自己的 integrator 继续写在 task。用户当前授权优先；独立执行者只在已有任务范围内兼任，不自封永久负责人。
2. 同一共享文件同一时刻一个实际写者。不同任务可有不同 integrator，但跨任务共享文件按具体文件／区段串行委派；登记“共同 integrator”不提供并发写入许可。
3. 正常退出保存检查点／最后交接并停止写入。用户已有指定或预授权时不重复审批；缺少授权时由用户指定继任，不能凭沉默、额度或超时自我接管。
4. 接班确认旧执行者停写、实际 Git 状态与最新交接，用接手者自己的文件确认，再更新共享协调记录和相关任务。异常退出可能无法再写最后交接，用此前检查点与 Git 恢复，不要求不可达旧执行者重新回应。
5. 空窗不设默认 24 小时，也不以超时作为授权。争议共享文件暂停写入；原本已授权、互不冲突的独占工作和只读调查仍可继续。
6. 异议写在提出者自己的消息文件，integrator 在相关 task 的 Problems 记录证据、处理与理由。权限／范围争议或验证无法解决的设计争议交用户；没有回应不意味着共识。
7. task 是否 done 取决于交付范围和验收；缺少继任建议不能将已完成任务倒退为 blocked。共享负责人状态 active / handoff_pending / vacant 单独记录。
8. 提前保存检查点，避免把最后一句交接当唯一恢复依据。文件协议不自动停止、派发或唤醒其他客户端。

## 与原提案的差异

采纳指定来源、唯一写者、继任、异议和交接的需求。修正“登记表保存实时整合者”“退出后必须重新等用户批准”“默认等 24 小时”“无继任建议就 blocked”以及必须由旧执行者最终确认的前置条件；这些条款会增加漂移、重复审批或恢复死锁。

原文保存于 Git，逐项裁决见 [gpt-001](../../.agents/messages/COLLAB003/gpt.md)，执行规则见 [核心协议](../../.agents/PROTOCOL.md) 与 [按需继任指南](../../.agents/guides/coordination.md)。

## 限制

这是约定，不是访问控制、身份认证、互斥锁或事务服务。跨机器自动继任仍需要真实共享存储、接收回执与执行者停止机制。本轮没有实施自动余额查询、自动轮换或外部通知。
