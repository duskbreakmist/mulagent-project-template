## 额外边界

1. **自复制不等于自动通用化。** audit-a 将第一代 agents_list.md 替换为明确实验标记并提交，再以它为来源安装第二代，实际登记标记随 seed 被复制；第二代 checker 仍通过。源码 tools/template_manager.py:21–25、212–215 与此一致：init 原样复制 seed，update 才保护已有工程状态。已使用业务工程若要成为新分发源，应先整理种子，当前没有专门的提升／去状态导出命令。
2. **通用检查器没有完整覆盖母模板维护路径。** audit-b 在隔离副本的 docs/maintenance/tasks 插入非法 status，checker 仍通过；tools/check_template.py:90–102 扫描的是 .agents/tasks。它按分发清单检查本地链接，不等于维护记录全部有效，也不核验真实 AI 在线或结果真实性。这一边界值得补检查，但本轮只评估，未改实现。
3. **完整 Git clone 与默认 init 的目的不同。** 完整 clone 可以取得母模板源码、测试、CI 与维护入口；默认 init 安装的是业务协作骨架。分发清单精简本身有合理用途，不能为了“自举”称谓直接扩大业务安装包。
4. **调度机制已有部分闭环基础。** tools/agent_workbench.py:323–356 已检查开发／测试角色和相同 revision，将失败反馈路由到开发者并恢复 todo。缺的是实际运行和验证真实产出、自动调度后续修复／再测试等端到端证明，不应把已有状态机说成全部缺失。revision 当前为字符串，尚不直接核验它在目标 Git 仓库中存在。

环境：Windows PowerShell、Python 3.13.8、Git 2.47.1.windows.2。沙箱内重跑先后在系统 TEMP 和工程 .test-tmp 创建临时 .agents 遇到 WinError 5；获自动审核允许后在沙箱外隔离执行成功。没有修改生产实现规避限制。完整测试日志保存在本机忽略目录 `.test-tmp/BOOT001-tests-unrestricted.log`；候选目录保留各自实验脚本与原始输出。交付链接检查还发现维护历史 DOC002 指南链接少一层上级路径，已修复该引用，历史结论保留。

尚未验证：真实外部 AI／额度接力、实际独立测试 Agent 的自动修复循环、后台写者停写、跨机器／本轮其他操作系统、新一轮远端 CI 或发布。本轮没有修改模板逻辑、自动推送或启动其他桌面 AI。

## 实用判断与下一步

若目标是“用这套规则让我们持续开发这套模板”，现在已经可以实施，本轮调查就是一次应用。若目标是“让它自己持续改进”，建议先限定一个维护任务，接入一个真实前台 AI 适配器和独立测试执行器，在隔离 worktree 中实测：开发提交→核验真实 revision→运行测试→失败反馈→修复新提交→重新测试→成功后停止。无需先建设整个平台，也不把人对目标与权限的决定算成项目自动能力。
